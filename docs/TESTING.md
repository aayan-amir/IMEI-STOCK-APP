# Local verification

Use Node 20.19.0 or later (the lock's minimum); CI checks the minimum and Node 24. No application import loads `.env`, connects to MongoDB, listens, or changes indexes. `npm start` explicitly loads local environment and starts the app. Automatic index creation and the historical startup index drop are disabled; schema/index changes now require explicit migration work.

```powershell
npm ci --ignore-scripts --no-audit --no-fund
npm run test:prepare-db
npm test
npm run check
```

`test:prepare-db` is the only test command that downloads a MongoDB binary. It pins MongoDB 8.2.6 and stores it under ignored `node_modules/.cache/mongodb-binaries`. Installation skips lifecycle scripts. Ordinary tests disable runtime downloads and fail explicitly if preparation is missing. On Windows the upstream archive is large; prepare once per dependency/cache reset.

`npm test` runs all current unit and integration checks. `npm run test:unit` and `npm run test:integration` run the respective groups. Local HTTP tests require permission to use loopback sockets in restricted environments. They never call the hosted API. Integration fixtures start a new loopback-only, one-member replica set on a generated port with a unique `stockly_test_` database and tenant ID, explicitly create test indexes, then disconnect and stop only that fixture. They neither read `.env` nor accept a supplied business database URI. A real replica set is used rather than mocking database behavior.

Unit checks cover runtime/test-target validation, import side effects, client API failures, selected UI state transitions with DOM stubs, and authorization contracts. Local HTTP checks run the actual middleware with a disconnected database stub. MongoDB integration checks exercise actual authentication/session and ownership routes with synthetic records. DOM stubs are not browser, camera, accessibility, visual, or Android acceptance evidence. Those suites and the broader inventory/accounting migration checks remain subsequent plan work.

Local browser API requests now use the current origin. Packaged Capacitor requests use the explicit HTTPS origin in `public/js/config.js`; choose its environment before native sync/build. A localhost browser must never silently use hosted shop data.

Platform administration is disabled without `SUPER_ADMIN_PASSWORD`. Existing client sessions without a version remain compatible while their Client has no version; a supported credential/status/shop save rotates a random authorization version and prevents old sessions from becoming valid after reactivation. Legacy direct-database utilities bypass this application lifecycle and remain unsuitable for routine maintenance.
